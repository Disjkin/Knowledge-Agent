# 改进计划：网搜兜底 + 执行链路追踪

> 本文档是开发任务书，交给开发模型直接实施。已包含现状分析、模块设计、数据结构、配置项、实施步骤与验收标准。
> 项目根目录：本项目根目录（按实际部署路径调整）

---

## 0. 背景与目标

当前项目是一个本地 RAG 知识库助手（FastAPI + LangChain + Chroma + SSE 流式 Web UI）。用户提问后，系统从本地向量库检索片段，拼入提示词调用 LLM 回答；检索不到时直接回复"知识库中未找到相关信息"。

本次迭代两个目标：

1. **网搜兜底**：当本地知识库找不到相关内容（无检索结果，或相关性分数低于阈值）时，自动调用网搜工具获取信息，用网搜结果继续回答，并在 UI 上明确区分来源。
2. **执行链路追踪（Trace）**：把每次用户 query 的完整工作链路落盘保存——包括 query 本身、各步骤的调用时间/耗时、每步调用工具的入参、每步返回结果（截断保存）、最终答案与是否走了网搜。

## 1. 现状代码摘要（实施前必读）

```
app/
├── main.py            # FastAPI 路由；/api/chat 用 SSE 调用 stream_chat()
├── config.py          # pydantic-settings 读 .env，Settings 类 + 全局 settings
├── config_admin.py    # 运行时模型设置（/api/settings）
├── llm/factory.py     # get_llm() / get_embeddings()
├── rag/
│   ├── ingest.py      # 文档入库（本次不动）
│   ├── retriever.py   # get_retriever(): Chroma as_retriever(similarity, k) —— 不带分数
│   └── chain.py       # stream_chat(question): 检索 → sources 事件 → LLM 流式 → done
├── models/schemas.py  # ChatRequest / SourceChunk 等
└── static/app.js      # 前端 SSE 解析：token / reasoning / sources / error / done
```

**当前 `stream_chat()` 事件序列**：`sources → token × N → done`（异常 `error`）。

**关键限制**：
- `retriever.py` 用 `as_retriever(search_type="similarity")`，**拿不到相关性分数**，无法判断"检索结果质量够不够"。需要改成直接调 vectorstore 的 `similarity_search_with_relevance_scores()`（langchain-chroma 支持，返回 `(Document, score)`，score 归一化到 (0,1]，越高越相关）。
- `chunks_to_sources()` 输出的来源卡片没有"知识库 / 网络"类型区分，也没有 URL 字段。
- 前端 `handleFrame()` 只识别 5 种事件，新事件需要同步加分支。

## 2. 需求一：网搜兜底

### 2.1 触发条件（规则判定，不接 LLM 判断）

满足任一即触发网搜：

- 本地检索结果为空（`len(chunks) == 0`）；
- 本地检索最高分 `< RELEVANCE_THRESHOLD`（默认 `0.3`，`.env` 可调）。

> 说明：Chroma 默认 L2 距离，langchain-chroma 归一化公式为 `1/(1+distance)`；若集合元数据是 cosine 空间则为 `1-distance`。两者都是"越大越相关"，0.3 是保守起点，后续按 trace 日志里的分数分布调优。

另设总开关 `WEB_SEARCH_ENABLED`（默认 `false`，未配置 key 时自动降级为不启用并打印 warning）。

### 2.2 新增模块 `app/tools/web_search.py`

统一接口，屏蔽供应商差异：

```python
# 返回结构（List[dict]）：
# {"title": str, "url": str, "snippet": str, "content": str}
async def search_web(query: str, max_results: int) -> list[dict]
```

供应商通过 `WEB_SEARCH_PROVIDER` 配置：

| provider | 依赖 | 说明 |
|---|---|---|
| `tavily`（默认，推荐） | `tavily-python` 或 `langchain-tavily` | 注册即送免费额度，中文可用，稳定性好；需 `TAVILY_API_KEY` |
| `duckduckgo`（免费备选） | `duckduckgo-search` | 无需 key，但国内网络可达性不稳定，需超时+异常兜底 |

要求：
- 全程异步（tavily 用 `AsyncTavilyClient`；duckduckgo 同步库用 `asyncio.to_thread` 包装）；
- 超时控制 `WEB_SEARCH_TIMEOUT`（默认 10s）；
- **网搜失败不能打断聊天**：捕获所有异常，返回空列表并在 trace 中记录 error；
- 结果去重（按 url），snippet/content 截断到 500 字符以内再入上下文。

### 2.3 `chain.py` 流程改造

新流程（替换 `stream_chat` 的步骤 1–3）：

```
1. kb 检索（带分数）
   → 记录步骤 trace（见需求二）
   → yield ("sources", {chunks, type:"kb"})        # 先推本地卡片（如有）
2. 判定是否网搜（见 2.1）
   → 若触发:
     a. yield ("status", {"stage":"web_search", "message":"本地知识库未找到，正在联网搜索…"})
     b. await search_web(question, WEB_SEARCH_MAX_RESULTS)   # trace 记录
     c. yield ("sources", {chunks: web_chunks, type:"web"})  # 网搜卡片单独一组
3. 合并上下文:
   - 两组都有 → 上下文分两段:【本地知识库资料】+【网络搜索资料】
   - 只有 web → 只用【网络搜索资料】
   - 都没有 → 保持原行为("知识库中未找到相关信息。") + trace 落盘
4. 拼提示词 → LLM 流式（原有逻辑不动，加 trace）
5. done 事件扩展: {"trace_id": ..., "used_web_search": bool}
```

`chunks_to_sources()` 扩展：每个 chunk 增加 `type`（`"kb"` / `"web"`）与 `url`（web 才有）字段；web 片段的 `source` 填标题、`file_name` 填域名。

`SYSTEM_PROMPT` 更新要点：
- 允许参考资料包含"本地知识库"与"网络搜索"两类，并在规则中说明；
- 引用格式：本地 `[来源: 文件名#片段编号]`，网络 `[来源: 标题](URL)`；
- 若使用了网络资料，回答末尾需注明"以上内容包含网络搜索结果，请注意甄别时效性"。

### 2.4 前端变更（`static/app.js` + `style.css`）

1. `handleFrame()` 新增 `status` 事件分支：在答案气泡上方显示一行灰色小字状态（如"🌐 正在联网搜索…"），下一个事件到达后移除或替换；
2. `renderSources()` 支持 `type`：
   - `web` 类型卡片标题改为 `🌐 网络来源 (N)`，条目渲染为可点击链接（`<a href=url target=_blank rel=noopener>`），样式与本地卡片区分（如左侧 3px 蓝色边条）；
3. `done` 事件可选：读取 `trace_id`，在答案气泡底部加一行淡色小字 `trace: <前8位>`，方便对照日志排查（可用配置开关，默认显示）。

## 3. 需求二：执行链路追踪（Trace）

### 3.1 新增模块 `app/tracing/tracer.py`

```python
class Tracer:
    """一次 query 一条 trace。步骤用上下文管理器计时。"""
    def __init__(self, query: str, history_len: int): ...
    def step(self, name: str, inputs: dict): ...   # 返回 contextmanager
    def set_result(self, answer: str, used_web_search: bool, model: str): ...
    def set_error(self, message: str): ...
    def save(self): ...   # 追加写入当天 JSONL 文件

def get_tracer(query, history_len) -> Tracer  # 工厂；TRACE_ENABLED=false 时返回空操作实现
```

### 3.2 存储格式

- 位置：`logs/traces/YYYY-MM-DD.jsonl`（按天滚动，自动建目录；**请求结束时一次性写入一整行**，避免并发写交错；加 `threading.Lock` 兜底）；
- 一行 = 一个完整 trace，结构如下：

```json
{
  "trace_id": "uuid4",
  "created_at": "2026-07-30T10:56:56.123456+08:00",
  "duration_ms": 4231,
  "query": "用户原始问题",
  "history_len": 0,
  "model": "openai:deepseek-chat@https://api.deepseek.com",
  "used_web_search": true,
  "status": "ok | error",
  "error": null,
  "steps": [
    {
      "seq": 1,
      "name": "kb_retrieve",
      "started_at": "2026-07-30T10:56:52.001+08:00",
      "duration_ms": 312,
      "inputs": {"query": "...", "k": 5, "threshold": 0.3},
      "outputs": {"hit_count": 5, "max_score": 0.61, "chunks": [{"source": "a.pdf#0", "score": 0.61, "snippet": "前200字..."}]},
      "status": "ok",
      "error": null
    },
    {
      "seq": 2,
      "name": "web_search",
      "started_at": "...",
      "duration_ms": 1830,
      "inputs": {"query": "...", "provider": "tavily", "max_results": 5},
      "outputs": {"hit_count": 5, "results": [{"title": "...", "url": "...", "snippet": "前200字..."}]},
      "status": "ok",
      "error": null
    },
    {
      "seq": 3,
      "name": "llm_stream",
      "started_at": "...",
      "duration_ms": 2089,
      "inputs": {"model": "deepseek-chat", "context_chars": 3200, "prompt_messages": 2},
      "outputs": {"answer_chars": 456, "finish": "done"},
      "status": "ok",
      "error": null
    }
  ],
  "answer": "最终答案全文（超长截断，见配置）"
}
```

字段规则：
- 所有时间用本地时区 ISO 8601（`datetime.now().astimezone().isoformat()`）；
- `inputs` 必须包含该步**真实入参**（检索的 query/k/threshold、网搜的 query/provider/max_results、LLM 的模型与上下文长度）；
- 长文本字段（snippet、answer）按 `TRACE_MAX_FIELD_LEN`（默认 2000 字符）截断，截断后追加 `"...[truncated]"`；
- 任何步骤异常：`status="error"` 且 `error` 记录异常信息，trace 仍须在 `finally` 中落盘。

### 3.3 集成点

- `chain.stream_chat()`：入口创建 tracer → 各步骤包进 `tracer.step(...)` → LLM 流结束后 `set_result()` → `finally: tracer.save()`；
- `main.py` 的 `/api/chat` 异常分支不改动（chain 内部已兜底落盘）；
- trace 读写全部放 `app/tracing/`，与业务代码解耦；`TRACE_ENABLED=false` 时零开销（no-op 实现）。

### 3.4 查询接口（Phase 2，可选，建议一并做）

- `GET /api/traces?limit=20&offset=0`：按时间倒序返回摘要列表（trace_id、created_at、query 前 80 字、duration_ms、used_web_search、status）；
- `GET /api/traces/{trace_id}`：返回完整 JSON；
- 实现方式：倒序读最近几天的 JSONL 即可，不引入数据库。

## 6. 验收标准

### 6.1 测试用例

1. **本地命中**：问知识库已有内容 → 不触发网搜，来源卡片只有本地；trace 里只有 `kb_retrieve` + `llm_stream` 两步，`used_web_search=false`；
2. **本地未命中**：问知识库外问题（如"今天的新闻"）→ 触发网搜，UI 依次出现状态行、🌐 网络来源卡片；回答含 URL 引用；trace 三步齐全，网搜步的 inputs 含 query/provider/max_results，outputs 含结果列表；
3. **低分触发**：问与库内文档擦边但不相关的问题 → 最高分 < 阈值时触发网搜（用 trace 里的 `max_score` 验证）；
4. **网搜失败降级**：故意填错 `TAVILY_API_KEY` → 聊天不中断，正常给出"未找到"类回答，trace 里 web_search 步 `status=error`；
5. **开关关闭**：`WEB_SEARCH_ENABLED=false` → 行为与旧版完全一致；
6. **trace 落盘**：每次问答后 `logs/traces/当天日期.jsonl` 增加一行合法 JSON，包含 query、各步骤时间/耗时/入参/结果、answer；并发连发两问，两行各自完整不串行；
7. **长文本截断**：answer 超过 `TRACE_MAX_FIELD_LEN` 时被截断且有标记。

### 6.2 完成定义

- 上述用例全部通过；`README.zh-CN.md` 补充新配置项说明；
- 代码不破坏现有行为（关网搜、关 trace 时与旧版一致）。

## 7. 风险与注意事项

- **网络可达性**：DuckDuckGo 在国内不稳定，默认用 tavily；网搜必须设超时，绝不能阻塞 LLM 主流程；
- **分数阈值**：不同嵌入模型/距离空间的分数分布不同，0.3 只是起点——上线后根据 trace 日志中 `max_score` 分布调整；
- **隐私**：trace 会落盘用户 query 与答案全文，目录限本地使用，勿提交 git；
- **并发**：多请求并发写 JSONL 必须"整条组装完一次 append + 锁"，禁止逐字段写；
- **上下文膨胀**：网搜 content 必须截断后再拼 prompt，避免超长导致 LLM 报错或成本飙升。
